# Flow cards

_Part of [architecture](../architecture.md); moved from "Flow" (#120)._

- **Flow** (`src/flow/index.ts`, cards in `drivers/timebox/driver.flow.compose.json`) — `registerTimeboxFlowCards(flow:
  FlowLike, translate: (key: string) => string)` (structural type, `asFlow(homey.flow)` proves it at compile time; `translate` is `homey.__`
  and localises argument errors, see "User-facing errors") is called from `TimeboxDriver.onInit`.
  Triggers `timebox_connected` / `timebox_disconnected` are fired by the device (`getDeviceTriggerCard(id).trigger(this)`,
  log `[device] flow trigger <id>`) when `onOnlineChanged` fires; trigger `timebox_channel_changed` (token `channel` = stable
  id, e.g. `lighting`) fires on every channel change, whoever made it (see "Mode picker"); trigger `timebox_countdown_ended` (no tokens; `FLOW_TRIGGER_COUNTDOWN_ENDED`) fires once per unsolicited end frame `71 55 03 01 01 00` of the device (#101, see "Countdown"); condition `timebox_channel_is`
  (dropdown of the three ids `clock`, `lighting`, `custom`; `device.getChannel()`: the controller's known mode, null while the device shows cloud or visualizer (condition false for every mode), else the stored capability value);
  action `timebox_set_channel` (same dropdown, `device.switchChannel(id)`, the id is validated again with `parseChannelId`); action `timebox_show_clock` (dropdown `style` of the seven clock style ids, `color` argument, `device.showClock(parseClockStyleId(style), parseHexColor(color))`; see "Clock face"); action `timebox_set_lighting` (`color` argument, `device.setLighting(parseHexColor(color))`; see "Power and lighting"); action `timebox_show_custom_page` (dropdown `page`, ids `"1"`..`"3"`, `device.showCustomPage(parseCustomPageId(p))`; see "Custom pages"; actions `timebox_show_text` (`text`, `color`, `background`, `speed` dropdown `slow`/`normal`/`fast`, `duration` number 0..3600; `device.showText({text, color: parseHexColor(color, 'text_color'), background: parseHexColor(background, 'background'), speed: parseTextSpeedId, durationS: parseTextDurationArg})`) and `timebox_stop_text` (`device.stopText()`); see "Native text"; actions `timebox_start_countdown` (numbers `minutes` 0..99 and `seconds` 0..59; `device.startCountdown(parseCountdownArgs(minutes, seconds))`) and `timebox_stop_countdown` (`device.stopCountdown()`); see "Countdown"; actions `timebox_show_image` (droptoken `image` passed as `droptoken`, dropdown `fit` `cover`/`contain`, number `duration` 0..3600; `device.showImageToken(droptoken, parseImageFitId(fit), parseTextDurationArg(duration))`) and `timebox_show_image_url` (text `url`, the same `fit` and `duration`; `device.showImageFromUrl(parseImageUrl(url), parseImageFitId(fit), parseTextDurationArg(duration))`); see "Show image"; action `timebox_set_temperature` (number `temperature` -99..99; `device.setWeather({temperatureC: parseTemperatureArg(t)})`) and action `timebox_set_weather` (dropdown `condition` of the six ids; `device.setWeather({condition: parseWeatherConditionId(c)})`); each passes only its part, invalid input never reaches the device; see "Weather"; the action `timebox_show_visualization` was removed in #68, a Flow that still uses it is broken); condition `timebox_is_connected` (title `!{{is|is not}}`)
  returns `device.isConnected()` (= the controller's `online === true`: the same "session answered a status query" state as availability and the triggers; false before the first answer, after the grace period expired and after `stop()`, but true during a short reconnect inside the grace period).
  Homey Compose adds the `device` argument (`driver_id=timebox`) to the driver's cards. The action `timebox_sync_time`
  ("Sync time now") was removed in #70 (a Flow that still uses it is broken; the time is set automatically, see "Time sync"). The mode cards (ids keep "channel") have `title` and `titleFormatted` in en/de. No user-visible text (compose, locales, `app.json`) mentions the removed 24-hour / status interval settings or "Sync time now" (guarded by `src/manifest.test.ts`).
