# UAT v0.5.0: Images

**Status:** accepted 2026-10-08
**Build:** `main` @ `ad78269` · **UAT issue:** #128 · **Issues:** #31 #101

## Preconditions
- Build installed (see `docs/uat/README.md`: checkout the build commit, `npm ci && npm run build`,
  `scripts/homey-run.sh stop --uninstall`, `homey app install`), Timebox Evo switched on, 1-2 m from the Homey, the Divoom
  phone app closed and the Evo not connected to any phone (it accepts one connection).
- The device is paired (a v0.4.0 device is fine and is kept; the new cards appear without re-pairing). Homey app language
  English; repeat UAT-12 with German.
- A webcam or your eyes on the Evo display.
- Test pictures: a colourful square PNG, a wide photo JPEG (landscape, for example 1920x1080), a large photo JPEG (3840x2160,
  under 5 MB), a GIF (animated is fine, only the first frame is shown), a PNG with transparency, a PDF or text file for the
  unsupported case, and a picture over 5 MB or over 8.3 MP. Put them on a web server Homey can reach (your own NAS or any
  public image URL), and keep the URLs handy.
- For UAT-4 and UAT-5: an image tag in a Flow, for example a camera snapshot (a Homey camera device "Snapshot taken" tag) or an
  album cover tag from a media app. Also the Homey mobile app with push notifications for UAT-8.
- Create a test Flow with a button trigger (or use the "Test" button of each card in the Flow editor) for each action card.
- Cases marked `[auto]` can be driven by the tester agent (the URL card and the trigger run via `scripts/homey-api.sh`, the
  log via `scripts/homey-run.sh log`, webcam via `scripts/hw-snap.sh`) in a `homey app run` (DEBUG) session. Pairing is always
  by hand. Cases without the mark are owner-only: the image-tag card (the Web API cannot pass an image tag), the Flow editor
  UI, push notifications, texts in German, and anything done on the device itself.
- Sending one picture takes about 5-6 s over Bluetooth; large pictures need a few more seconds to prepare. Colours are judged
  by eye: the picture is shrunk to 16x16 pixels.

## Known open issues (not failures of this round)
- Images (#31): only PNG, JPEG and GIF (first frame), at most 5 MB, 8.3 megapixels (3840x2160) and 16384 pixels per side; no
  rotation by the EXIF flag of a photo (a portrait photo taken sideways may show sideways), no colour profiles.
- Images (#31): the image is not a mode. The tile and the mode picker do not change while it is shown; there is no "Stop
  image" action, any mode change, a text, a countdown or switching the Evo off ends it. A mode change at the Evo itself
  (buttons, Divoom app) ends it in the app at the next status poll (up to about 15 s).
- Images (#31): an image that is still shown when the app restarts is not known to the app; any mode change ends it. If the
  link is down when the duration ends, the image stays until the next mode command.
- Images (#31): an image shown over a running countdown is replaced by the clock when the countdown ends, but the app still
  thinks the image is shown (weather updates are held until the next display command).
- Countdown ended (#101): the trigger fires for every end the Evo reports, also for a countdown that a mode change, a text or
  power off had hidden, and one started on the Evo or in the Divoom app. It does not fire for "Stop countdown".
- Countdown ended (#125): when the end display lights a panel that was off, the tile "on/off" stays off although the panel is lit.
- Earlier known limits of text, weather and countdown (v0.4.0) still apply.

## Test cases
### UAT-1 New cards are present (#31 #101)
1. Open the Flow editor. Add an action, choose the Timebox device. Add a trigger "When ..." and choose the Timebox device.
**Expected:** The actions "Show image" (with an image tag field, "Fit" and "Duration (s)") and "Show image from URL" (URL, Fit,
Duration) exist next to the earlier ones. The trigger "Countdown ended" exists (no tags). "Fit" offers "Fill the display (crop)" and
"Whole image (black bars)"; the duration hint says "0 = until a mode change". The app asks for no new permission. The tile
still works (power, brightness, colour, mode).

### UAT-2 Show image from URL, fill the display (#31) [auto]
1. Flow action "Show image from URL": the URL of the colourful square PNG, Fit "Fill the display (crop)", duration `0`. Run it
   from the clock.
2. Run it again with the wide 1920x1080 photo JPEG, Fit "Fill the display (crop)".
**Expected:** After about 5-8 s the Evo shows the picture as a recognisable 16x16 mosaic of it (square PNG: whole picture; wide
photo: the centre square, the left and right sides cut off). The action returns without an error. The tile and mode picker
do not change (the image is not a mode). The second run replaces the first. The picture stays on the display (look again after
a minute).

### UAT-3 Fit "Whole image" and transparency (#31) [auto]
1. Run "Show image from URL" with the wide photo JPEG, Fit "Whole image (black bars)", duration `0`.
2. Run it with the PNG with transparent areas, Fit "Whole image".
3. Run it with the GIF.
**Expected:** 1. The whole photo is visible, 16 pixels wide and about 9 rows high, centred with black bars above and below.
2. Transparent areas are black. 3. The first frame of the GIF is shown (no animation).

### UAT-4 Show image with an image tag (#31)
1. In the Flow editor build a Flow: a trigger that provides an image tag (for example a camera "Snapshot taken", or "Album
   art changed" of a media app, or an "Image" tag from a webhook), then the action "Show image". Drop the image tag onto the
   card's image field. Fit "Fill the display (crop)", duration `0`.
2. Run the Flow (use the trigger's "Test" or cause the real event).
3. Change Fit to "Whole image (black bars)" and run again.
**Expected:** After about 5-8 s the Evo shows a 16x16 mosaic of the camera snapshot or the album cover. The action returns
without an error and without a hang. Step 3: the whole picture with black bars. No "Memory" or restart of the app (Homey >
Apps > Divoom Timebox keeps running).

### UAT-5 Image tag errors (#31)
1. Run the "Show image" card without dropping an image tag on it (leave the field empty) if the editor lets you save it, or
   with a tag that has no image yet (for example a snapshot Flow that failed).
**Expected:** The action fails with "No image was given. Drop an image tag onto the card." The display stays as it was.

### UAT-6 Image with a duration (#31) [auto]
1. Start the clock (tile mode Clock). Run "Show image from URL" with the PNG, duration `15`. Time it.
2. Repeat from the Lighting mode.
**Expected:** The picture shows for about 15 s (counted from the moment it is shown, the sending takes a few seconds), then the
Evo returns to the previous mode (the clock with its style, or the lighting colour). The tile did not change in between.

### UAT-7 Image is ended by text, countdown, mode change, power off or a newer image (#31) [auto]
1. Show an image (duration `0`). Run "Show text" (duration `0`), then "Stop text".
2. Show an image. Run "Start countdown" 0:30.
3. Show an image. Select another mode on the tile (for example Lighting), then show an image again and switch the tile off
   and on.
4. Show image A, then image B.
**Expected:** 1. The text replaces the picture at once; after "Stop text" the mode is shown, the picture does not come back.
2. The countdown replaces the picture. 3. Each ends the picture at once; nothing comes back after switching on again.
4. B replaces A. No error in any case.

### UAT-8 Flow: When Countdown ended, push notification (#101)
1. Create a Flow: "When" the Timebox "Countdown ended" > "Then" the Homey app "Send a push notification" with the text "Timebox
   countdown finished". Save it.
2. Run "Start countdown" with 0 minutes and 20 seconds (from the clock). Wait for the end.
3. Check the push notification and the Homey Insights/Flow history if you like.
**Expected:** The Evo shows the hourglass counting down, then the end display (00:00) for a few seconds, then returns to the clock.
When the end display appears (within about 1-2 s), the Flow fires once and your phone receives exactly one push notification
"Timebox countdown finished". The tile does not change.

### UAT-9 Countdown ended: log check and no trigger on Stop (#101) [auto]
1. With the Flow of UAT-8 enabled (or `scripts/homey-run.sh log` for the tester), start a countdown of 5 minutes, wait 5 s and
   run "Stop countdown".
2. Wait 20 s.
3. Start a countdown of 0:15 and let it end.
**Expected:** Step 1/2: the Evo returns to the clock; no push notification and no trigger (log: no `flow trigger
timebox_countdown_ended`). Step 3: the log shows `countdown ended (device)` followed by `[device] flow trigger
timebox_countdown_ended` exactly once, and the push notification arrives once.

### UAT-10 Hidden countdown still fires the trigger (#101) [auto]
1. Start a countdown of 0:25, then at once run "Show text" (duration `0`). Wait 30 s. Run "Stop text".
**Expected:** The text hides the countdown; the countdown keeps running. At the original end time the end display flashes
briefly over the text/clock and the push notification arrives once. This is a known limit of the device (the app cannot see
the countdown), not an error.

### UAT-11 Image then countdown end (#31 #101) [auto]
1. Show an image (duration `0`), then start a countdown of 0:20 (the countdown replaces the picture). Let it end.
2. Show an image (duration `0`), then start a countdown of 0:20. Before it ends, show an image again.
**Expected:** 1. The countdown replaces the picture; at the end the end display shows, then the clock (the picture does not
come back); the trigger fires once. 2. The newer image replaces the countdown display; at the original end time the end display
may flash briefly (hidden countdown, known limit) and the trigger fires once.

### UAT-12 German texts (#31 #101)
1. Set the Homey app language to German; open the Flow cards.
**Expected:** "Bild anzeigen" ("Bild [Tag] anzeigen, [Einpassen], für [Dauer] s"), "Bild von URL anzeigen", trigger "Countdown
abgelaufen"; fit options "Display füllen (zuschneiden)" and "Ganzes Bild (schwarze Ränder)"; the hints are German. No raw keys and no
English leftovers. The errors of UAT-13 to UAT-16 are German as well ("Das Bild konnte nicht geladen werden. ...", "Das Bild ist zu
groß. Unterstützt werden höchstens 5 MB, 8.3 Megapixel und 16384 Pixel pro Seite.", "Das Bild kann nicht angezeigt werden.
Unterstützt werden nur PNG-, JPEG- und GIF-Bilder."). Switch back to English afterwards.

## Edge cases
### UAT-13 Unreachable URL and invalid address (#31) [auto]
1. "Show image from URL" with `https://does-not-exist.invalid/a.png`, then with a valid host but a path that gives a 404, then
   with an address that does not answer (a closed port on your LAN; the action ends after about 10 s).
2. "Show image from URL" with `ftp://example.com/a.png`, with `example.com/a.png` (no scheme) and with an empty URL.
**Expected:** 1. Each fails with "The image could not be loaded. Check the address and that Homey can reach it (the server must
answer within 10 seconds)."; no hang; the display stays as it was (a shown image keeps showing). 2. Each fails with a readable
error "URL: ... is not a web address the Timebox app can load. Use an http:// or https:// address of at most 2048 characters,
without a user name or password." Nothing is sent.

### UAT-14 Unsupported format (#31) [auto]
1. "Show image from URL" with the address of a text or PDF file, then of a web page (an HTML address), then of a WebP or BMP image.
**Expected:** Each fails with "The image cannot be shown. Only PNG, JPEG and GIF images are supported." The display stays.

### UAT-15 Large photo and too large images (#31) [auto]
1. "Show image from URL" with the 3840x2160 photo JPEG (under 5 MB), Fit "Fill the display" and run it three times in a row.
2. With a file over 5 MB.
3. With a picture over 8.3 megapixels (for example 5000x4000) or one with a side over 16384 pixels.
**Expected:** 1. Each run shows a recognisable picture after about 6-10 s; the app does not restart and shows no memory warning
(Homey > Apps shows Divoom Timebox running). 2. and 3. Fail with "The image is too large. At most 5 MB, 8.3 megapixels and
16384 pixels per side are supported." Nothing is sent; the display stays.

### UAT-16 Same errors from the image tag card (#31)
1. Drop an image tag with a very large or unsupported image (for example a WebP album cover or a 12 MP camera snapshot if you
   have one) on "Show image" and run it.
**Expected:** A readable error as in UAT-14 or UAT-15; no hang and no app restart. If the tag cannot be read at all: "The image
could not be read from the image tag. Try again, or use another source."

### UAT-17 Image while the panel is off (#31) [auto]
1. Switch the tile off (the panel is dark). Run "Show image from URL" with the PNG, duration `0`.
2. Switch the tile off again, run it with duration `15`.
**Expected:** 1. The panel lights and shows the picture (this can take a few seconds longer); the tile switches to on. 2. After
about 15 s the picture ends and the Evo shows the previous mode (the one from before it was switched off).

### UAT-18 Text after image (#31) [auto]
1. Show an image (duration `0`). Run "Show text" `Hello` with duration `10`.
**Expected:** The text replaces the picture at once. After about 10 s the text ends and the mode is shown; the picture does not
come back.

### UAT-19 Image change at the device (#31)
1. Show an image (duration `0`). Press the mode button on the Evo (or use the Divoom app) to change to another view.
2. Wait about 20 s, then change the mode in Homey with the tile.
**Expected:** 1. The Evo shows the new view; within about 15-20 s the tile follows (a change to a mode offered in the app) or is
cleared (a mode not offered). 2. The tile mode change works normally and no picture comes back.

### UAT-20 Device unreachable (#31 #101)
1. Switch the Evo off, wait until the tile is unavailable (about 30 s).
2. Run "Show image from URL" and "Show image".
3. Switch the Evo on again and wait for the tile to recover.
**Expected:** 2. No hang: both fail with "The Timebox is not connected right now. Try again in a moment." (nothing is
downloaded). 3. The tile recovers by itself; running the card then works. The "Countdown ended" Flow does not fire while the
Evo is off.

### UAT-21 Quick successive images (#31)
1. Press "Test" on a "Show image from URL" card three times within about 2 s, with different pictures.
**Expected:** No error toast and no stuck half-drawn picture; the newest picture is shown at the end (older ones are replaced; a
superseded action may report "image superseded by a newer image" in the log only).

## Regression smoke (v0.2.0 to v0.4.0, accepted)
- Pairing (v0.2.0): tile available within ~45 s with on/off, brightness, colour and mode.
- Availability: switch the Evo off for 1 min and on again; "Timebox disconnected"/"connected" fire once each, the tile recovers by itself.
- Mode picker (v0.3.0): Clock, Lighting, Custom switch the Evo within ~2 s; "Show clock" with a style and colour, "Set lighting", "Show custom page" work.
- Clock settings (v0.3.0): changing "Clock style" while the clock is shown updates the Evo at once; the clock does not show animation pages unless "Show animation pages" is on.
- Brightness slider and on/off tile follow the Evo without an error toast.
- Show text (v0.4.0): "Show text" `Hello Homey`, duration `0` scrolls; "Stop text" ends it and the mode is shown.
- Weather (v0.4.0): with "Show temperature" on, "Set temperature" `21` shows 21 °C on the temperature page; "Set weather" Snow shows snow.
- Countdown (v0.4.0): "Start countdown" 0:20 shows the hourglass and ends with the end display; "Stop countdown" returns to the previous view.
